# Передача архитектуры разработчику

## Что передать

Передавайте один каталог со следующим содержимым:

```text
identity-architecture/
├── architecture.vpp
├── README.md
├── catalog/
├── diagrams/
├── exports/
│   ├── identity-overview.pdf
│   ├── identity-domain.pdf
│   ├── identity-application.pdf
│   └── identity-infrastructure.pdf
└── identity-architecture-docs.zip
```

`architecture.vpp` содержит редактируемую модель и Class Repository. Markdown и PDF дают доступ к архитектуре без Visual Paradigm. В подготовленном текстовом комплекте `.vpp` и PDF пока отсутствуют: их нужно добавить после сохранения и экспорта актуальной модели из Visual Paradigm.

## Подготовка Visual Paradigm

1. Сохранить проект, чтобы в заголовке окна исчез символ `*`.
2. Открыть **View → Panes → Model Explorer** и проверить полное дерево модели.
3. Убедиться, что классы на диаграммах являются представлениями элементов модели, а не дубликатами с одинаковыми именами.
4. Заполнить поле **Documentation** у ключевых пакетов, классов и интерфейсов.
5. Для каждой диаграммы добавить UML Note с назначением, границами и основными решениями.
6. Проверить связи `Realization`, `Dependency`, `Association`, `Composition` и их направление.
7. Выполнить **Project → Export → PDF** либо экспортировать каждую диаграмму в PDF/SVG/PNG.
8. Скопировать сохранённый `.vpp` и экспорты в этот каталог.

## Экспорт Class Repository без Visual Paradigm

Чтобы разработчик видел все элементы модели без открытия `.vpp`, используйте оба представления:

- `catalog/classes.md` и `catalog/interfaces.md` — читаемый каталог с package path, назначением, полями и операциями;
- экспорт **Model → Report** или **Tools → Doc. Composer** из Visual Paradigm — автоматически сформированный HTML/PDF со всеми элементами модели и их Documentation.

Названия пунктов меню могут немного отличаться в разных редакциях Visual Paradigm. Если Doc. Composer недоступен в вашей лицензии, достаточно PDF-экспорта диаграмм и файлов каталога из этого комплекта.

## Интерактивный Model Explorer в браузере

Если разработчик должен самостоятельно выбирать пакеты, классы, диаграммы и читать их описания без Visual Paradigm, опубликуйте проект как локальный веб-сайт:

1. Выберите **Tools → Publish Project...**.
2. Укажите папку `exports/identity-web` в поле **Output directory**.
3. Откройте **Advanced Options...**.
4. Включите **Generate menu**, **Generate model element list in diagram page** и **Show description when hover over a shape**.
5. Не включайте **Generate only description in model element page**, иначе из страницы элемента будут исключены остальные свойства.
6. Не включайте **Generate only when description is defined**, чтобы в навигации остались все элементы модели.
7. При желании выберите общую диаграмму Identity как **Default diagram**.
8. Включите **Launch viewer** и нажмите **OK**.

Передавать нужно всю папку `identity-web`, сохраняя её внутреннюю структуру. После распаковки разработчик открывает `identity-web/index.html`. В опубликованном сайте доступны Diagram Navigator, Model Explorer, Class Navigator, страницы элементов, описания и relationships.

В текущем комплекте экспорт опубликован непосредственно в корень `docs/architecture`. Стартовый `index.html` заменён более читаемым интерфейсом с раскрывающимся деревом пакетов, поиском и вкладкой диаграмм. Стандартный интерфейс Visual Paradigm сохранён как `visual-paradigm-report.html`.

Если повторная публикация Visual Paradigm перезапишет `index.html` и `content/report.css`, улучшенный интерфейс можно восстановить скриптом `tools/build_readable_browser.py` или попросить Codex пересобрать его.

Альтернатива с исходным интерфейсом — передать `architecture.vpp` и использовать бесплатный Visual Paradigm Project Viewer. Этот вариант требует установки Viewer, но показывает исходную структуру проекта.

## Что проверить перед отправкой

- открывается копия `.vpp`;
- в Model Explorer видны `api`, `presentation`, `application`, `domain`, `infrastructure`;
- экспортированы все четыре основные диаграммы;
- в диаграммах не обрезаны классы и подписи связей;
- текст в PDF читается при масштабе 100%;
- относительные ссылки из `README.md` открываются;
- `exports/identity-web/index.html` открывает опубликованный проект и навигацию;
- версия документации и `.vpp` относятся к одной редакции архитектуры;
- в комплекте отсутствуют секреты, закрытые ключи JWT и реальные пароли конфигурации.

## Что разработчик должен получить из комплекта

После чтения документов разработчик должен однозначно понимать:

- какой пакет публичен для других модулей;
- какие use cases доступны Presentation;
- какие output ports обязан реализовать Infrastructure;
- где находятся транзакционные границы;
- какие инварианты защищают агрегаты;
- как создаются, передаются и сохраняются токены;
- какие таблицы, ограничения и индексы нужны;
- как Identity вызывает Notifications;
- какие зависимости запрещены;
- по каким критериям реализация считается завершённой.
