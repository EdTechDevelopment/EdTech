# Notifications

Notifications владеет очередью доставки, SMTP, шаблонами писем, попытками отправки и техническим статусом доставки. Бизнес-решение о необходимости письма принимает вызывающий модуль. Общая граница зафиксирована в [архитектуре backend](../BACKEND_ARCHITECTURE.md).

Для Tutoring нужны заявки на приглашение ученика, `dedup key`, атомарная постановка заявки в общую транзакцию и отправка после commit. Контактный email профиля не подтверждается и не вызывает отправку письма. Конкретные требования описаны в [итоговой архитектуре Tutoring](../tutoring/TUTORING_ARCHITECTURE.md). Отдельная полная спецификация внутреннего устройства Notifications в этом каталоге пока не утверждена.

Текущий `NotificationGateway.enqueue(SendVerificationEmailCommand)` обслуживает
только письма подтверждения Identity. При реализации Tutoring публичный
Notifications API расширяется заявкой на приглашение ученика. Каждая заявка несёт стабильный ключ
повтора; повтор с тем же ключом не создаёт второе письмо. Raw token или ссылка
временно находятся только в защищённой очереди доставки Notifications, а не в
таблицах Tutoring. Identity outbox для межмодульных событий — отдельный механизм.
