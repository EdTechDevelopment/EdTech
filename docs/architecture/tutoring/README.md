# Архитектура Tutoring

Эта папка содержит согласованную проектную спецификацию модуля Tutoring. Она описывает целевую архитектуру, а не реализованный код: Java-классы, миграции, HTTP-контроллеры и сквозные тесты Tutoring ещё предстоит написать.

## С чего начать

1. [Итоговая архитектура](TUTORING_ARCHITECTURE.md) — каноническая сводка границ, слоёв, контрактов, хранения, интеграций и критериев готовности.
2. [Этап 1: границы и сценарии](tutoring-stage-1-boundaries-and-use-cases.md) — предметные решения.
3. [Этап 2: публичный Java API](TUTORING_STAGE_2_PUBLIC_API.md) — межмодульные контракты.
4. [Этап 3: Domain](TUTORING_STAGE_3_DOMAIN.md) — агрегаты, операции и инварианты.
5. [Этап 4: Application](TUTORING_STAGE_4_APPLICATION.md) — структура и координация сценариев.
6. [Подробные сценарии Application](TUTORING_APPLICATION_SCENARIOS.md) — единый документ по Subject, Profile, Idempotency, Integration, Invitation и Relationship.
7. [Этап 5: Infrastructure и Presentation](TUTORING_STAGE_5_INFRASTRUCTURE_AND_PRESENTATION.md) — PostgreSQL, адаптеры, HTTP и проверки.

## Правило чтения

Более поздние согласованные решения уточняют ранние этапы. При расхождении используйте итоговую архитектуру и соответствующий предметный раздел этапа 5. В частности, ученик может не выбирать предметы; дата рождения копируется из Identity в учебные профили и видна другому пользователю только при подтверждённой связи; отдельной настройки её видимости нет.

Проектирование Tutoring завершено на уровне этих спецификаций. Для реализации потребуются изменения контрактов Identity и Notifications, Scheduling guard для отвязки, общие транзакционные workflows, миграции и тесты. Подробный перечень зависимостей и критериев завершения приведён в итоговой архитектуре.
