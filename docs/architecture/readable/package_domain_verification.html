Назначение пакета

Определяет агрегат EmailVerification и связанные с ним доменные типы. Агрегат управляет жизненным циклом одноразового подтверждения email: хранит только хэш токена, назначение подтверждения, целевой адрес, срок действия, время использования и время аннулирования.

EmailVerification ссылается на агрегат User только через userId и не получает объектную или ORM-связь с User. Изменение User после проверки токена координируется application-сервисом.

Классы и интерфейсы

4
◇
EmailVerification
Класс
Корень агрегата подтверждения email. Представляет одно подтверждение первоначального адреса или изменения текущего адреса пользователя. Агрегат хранит только хэш токена и запрещает повторное использование, использование после истечения срока действия и использование после аннулирования. Срок действия нового подтверждения составляет 24 часа. EmailVerification не активирует User и не изменяет его email напрямую. После успешного использования подтверждения application-сервис загружает User по userId и вызывает соответствующую доменную операцию.

◇
InvalidVerificationException
Класс
Возникает, когда EmailVerification невозможно использовать: срок действия истёк, подтверждение уже использовано или оно было аннулировано. Application-слой преобразует такие случаи в единую внешнюю ошибку INVALID_VERIFICATION_TOKEN, чтобы не раскрывать технические подробности проверки токена.

◇
VerificationPurpose
Класс
Определяет назначение подтверждения email. Назначение используется application-сервисом для выбора допустимой операции над агрегатом User после успешной проверки токена.
›
◇
VerificationTokenHash
Класс
Неизменяемый объект-значение, представляющий хэш одноразового verification token. Открытый токен существует только на границе сценария и никогда не сохраняется внутри доменной модели или базы данных. Объект не определяет конкретный алгоритм хэширования. Генерация и хэширование токена выполняются через выходные порты application-слоя.
