identity.domain.user.model
Исходная спецификация VP

Назначение пакета

Содержит корень агрегата User, принадлежащие ему объекты-значения и перечисления. User является единственной точкой изменения состояния аккаунта и защищает его бизнес-инварианты.

Пакет не выполняет поиск уникального email, проверку открытого пароля, создание JWT, сохранение в базу данных или отправку писем. Эти действия координируются application-слоем через выходные порты.

Email
Класс
Неизменяемый объект-значение, представляющий нормализованный email пользователя. Проверяет обязательность значения, удаляет внешние пробелы и гарантирует допустимый формат адреса. Сравнение объектов Email выполняется по значению. Объект не проверяет уникальность адреса в системе, поскольку такая проверка требует обращения к repository.

PasswordHash
Класс
Неизменяемый объект-значение, представляющий результат безопасного хэширования пароля. Гарантирует, что внутри агрегата User хранится только непустой хэш, а не открытый пароль. Объект не знает конкретный алгоритм хэширования. Создание и проверка хэша выполняются через PasswordHasher, реализация которого находится в infrastructure.

User
Класс
Корень агрегата аккаунта пользователя. Хранит идентификатор, текущий и ожидающий подтверждения email, хэш пароля, имя, фамилию, роли, статус и временные метки. User является единственной точкой изменения состояния аккаунта. Он проверяет наличие хотя бы одной роли, запрещает недопустимые переходы статуса, управляет двухэтапной сменой email и не позволяет аутентификацию до подтверждения адреса. Класс не хранит открытый пароль, JWT, refresh token или технические данные persistence. Уникальность email проверяется application-сервисом через UserRepository.

UserRole
Класс
Определяет бизнес-роли пользователя в системе. Один пользователь должен иметь минимум одну роль и может одновременно иметь роли преподавателя и ученика. Роль не является отдельным пользователем, профилем или механизмом авторизации Spring Security. Профили преподавателя и ученика принадлежат модулю Tutoring.

UserStatus
Класс
Определяет текущее состояние аккаунта пользователя. Новый аккаунт ожидает подтверждения email и становится активным только после успешного подтверждения. Допустимые переходы статуса контролируются агрегатом User. Application и infrastructure не должны изменять статус напрямую.
