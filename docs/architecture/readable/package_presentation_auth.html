Назначение пакета

Группа HTTP-сценариев, связанных с регистрацией и аутентификацией

пользователя.

Пакет обслуживает регистрацию, подтверждение email, повторную отправку

письма подтверждения, вход, обновление токенов и выход.

Auth отвечает только за HTTP-представление этих сценариев. Он принимает

учётные данные и токены от клиента, передаёт их application use cases

и формирует соответствующий HTTP-ответ.

Пакет не сравнивает пароль с хэшем, не создаёт JWT, не проверяет

подпись JWT, не сохраняет refresh token и не загружает пользователя

из базы данных.

identity.presentation.auth.controller
Содержит REST-контроллеры сценариев регистрации и аутентификации. Контроллеры определяют URL, HTTP-метод, ожидаемый request и возвращаемый response. Они извлекают данные из JSON, заголовков и cookie, после чего передают выполнение входному application-порту. Контроллер может выбрать HTTP-статус, установить или удалить cookie и передать результат mapper-классу. Контроллер не должен содержать SQL, транзакции, бизнес-проверки, криптографические операции, генерацию токенов или непосредственные вызовы infrastructure.

cookie
identity.presentation.auth.cookie
Содержит HTTP-логику передачи refresh token через cookie. Пакет получает готовое значение refresh token от application и создаёт безопасную HttpOnly cookie для браузера. При logout пакет формирует cookie, удаляющую refresh token на стороне клиента. Пакет не создаёт JWT, не проверяет его подпись, не выполняет ротацию, не отзывает токен и не сохраняет refresh-сессию. Эти операции выполняются application и infrastructure.

mapper
identity.presentation.auth.mapper
Содержит преобразования между HTTP-моделями auth и моделями application. Mapper преобразует request DTO в application command и application result в response DTO. Преобразование должно быть детерминированным и не иметь внешних побочных эффектов. Mapper не обращается к repository, базе данных, JWT-провайдеру, SMTP и другим backend-модулям. Он не проверяет бизнес-правила и не управляет транзакциями.
