# Workflows

Workflows координирует процессы, затрагивающие несколько модулей; обычная логика одного модуля остаётся у его владельца. Общие правила приведены в [архитектуре backend](../BACKEND_ARCHITECTURE.md).

Согласованные для Tutoring внешние процессы: `RegistrationWorkflow`, `RoleOnboardingWorkflow`, `UnlinkStudentWorkflow`, `MeQueryFacade` и `StudentCardQueryFacade`. Их порядок вызовов и транзакционные требования описаны в [итоговой архитектуре Tutoring](../tutoring/TUTORING_ARCHITECTURE.md). Доверенные команды Tutoring вызываются из workflow в общей транзакции; прямыми пользовательскими endpoint они не являются.

| Процесс | Что делает | Публичная ручка |
|---|---|---|
| `RegistrationWorkflow` | Создаёт Identity User с `birthDate` и ровно один профиль на каждую роль в общей транзакции; ошибка откатывает всё. | `POST /api/v1/auth/register` с `Idempotency-Key: UUID`, ответ `202 VerificationPendingResponse` без токенов. |
| `RoleOnboardingWorkflow` | Добавляет вторую роль в Identity и соответствующий профиль Tutoring в той же транзакции. | `POST /api/v1/me/roles/teacher` или `/student` с ключом, ответ `201 MeResponse`; затем клиент обновляет JWT. |
| `UnlinkStudentWorkflow` | Сначала вызывает guard/обработку будущих уроков Scheduling, затем удаляет связь Tutoring. | `DELETE /api/v1/teachers/me/students/{studentUserId}` с ключом, ответ `204`. |
| `MeQueryFacade` | Собирает свой аккаунт Identity и self-view обоих профилей. Роль без профиля — ошибка целостности. | `GET /api/v1/me`. |
| `StudentCardQueryFacade` | Собирает публичные сведения активного профиля Tutoring; статистику уроков отдаёт лишь связанному преподавателю через Scheduling. | Составная карточка со статистикой реализуется вместе со Scheduling. |

Workflow не читает чужие таблицы и не заменяет бизнес-логику модулей. Для трёх изменяющих межмодульных запросов он хранит отображение `(сценарий, пользователь или регистрационный контекст, Idempotency-Key) → operationId` и при точном повторе использует тот же ID. Изменённые данные с тем же ключом дают `409`. Для регистрации сравнение включает пароль через защищённый серверным ключом fingerprint; сам пароль и raw token в журнале повторов не хранятся. Техническая схема записи, её защита при конкуренции и транзакционная связь с результатом уточняются в реализации Workflows.

Публичные просмотр и поиск активных профилей принадлежат Tutoring, а не `StudentCardQueryFacade`. Отсутствие связи не ограничивает доступ к дате рождения, выбранным предметам, описанию и подтверждённым контактам профиля. Списки связей и статистика уроков остаются отдельными защищёнными сценариями.
